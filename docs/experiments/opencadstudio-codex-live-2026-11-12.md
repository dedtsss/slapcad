# Первый реальный Codex → OpenCADStudio на HangarVPS (12.11.2026)

**Итог: автономное построение и сохранение 3D DWG через локальный MCP — ПОДТВЕРЖДЕНО.** Полный агентный сеанс завершён оператором после успешного DWG и независимой проверки: долгое исследование способов видов/экспорта расходовало вызовы инструментов. Итоговый текст Codex не был получен. PNG и PDF подготовлены отдельно непосредственно через OpenCADStudio.

## Конфигурация и авторизация

- Сервер: `hangarvps` (Ubuntu 24.04.5 LTS), пользователь `ocstest` без административных прав.
- Кодекс: `codex-cli 0.167.0` (`@openai/codex`), подтверждено `codex login status` = `Logged in using ChatGPT`. Файл учётных данных `/home/ocstest/.codex/auth.json` с правами 0600; **не читался, не копировался и не публиковался**.
- Модель `gpt-6.1-sol` задана CLI параметром `-m gpt-6.1-sol`. Действительный OpenAI вызов проверен по самостоятельным решениям модели и MCP; точные расходы по подписке не извлекались.
- Локальный MCP `opencadstudio` включён: `/usr/bin/xvfb-run -a -s '-screen 0 1440x960x24' /home/ocstest/opencadstudio/OpenCADStudio-v2026.45-linux-x86_64.AppImage --mcp`. Все CAD-инструменты исполняются непосредственно на HangarVPS. Межсерверные вызовы к BruceVPS **не использовались**.
- Сценарий `codex exec` в режиме `workspace-write` сначала не разрешил редактирование MCP (`MCP tool call requires approval, but approval policy is never`). Повторный штатный запуск с `--approve-for-me` позволил запросить и получить автоматическую проверку разрешений и реально выполнить построение. Режим `--dangerously-bypass-approvals-and-sandbox` **не включался**.

## Фактически сделанное моделью

По сохранённому событийному журналу `/home/ocstest/opencadstudio/results/sol-pilot/codex-live-20261112/events-review.jsonl`:
1. Codex самостоятельно вызвал MCP `ocs_sessions`, `ocs_read`, `ocs_commands`, изучил настоящий редактор и форматы команд, открыл новый документ.
2. Сам вызвал построение двух BOX (база, площадка), по идентификаторам объектов выбрал их и объединил с `UNION`.
3. Сам вызвал построение пяти реальных цилиндров с радиусами R12/R5 и выступом 1 мм, а затем `SUBTRACT` с выбором базового и режущих тел в несколько шагов. В результате 5 режущих тел удалены, основной `3D Solid` изменён.
4. `ocs_query` сообщил **одно тело**, `ocs_measure` подтвердил границы, `ocs_audit` для DWG 2018 дважды прошёл с **0 ошибок / 0 предупреждений**.
5. `ocs_save_verified` реально сохранил `codex-real-20261112-flange.dwg` и вернул `verified=true`. Codex также вызвал `ocs_open`, повторно прочитал модель и измерил объём.
6. Затем модель тратила время на изучение способов изометрического представления, печати и снимков, неоднократно вызывала справку `ocs_read`, `ocs_render` и файловые команды. После проверки сохранённой модели длинный сеанс **остановлен вручную**, чтобы не расходовать лимиты бесцельно. Это ограничение эффективности управления, а не отказ геометрического построения.
7. Снимок PNG и PDF дополнительно созданы **отдельным операторским испытанием OpenCADStudio** по уже сохранённому DWG. Они не должны приписываться автономному завершению моделью.

- внешние границы `[0,0,0]..[160,110,30]` мм;
- объём по сетке при новом чтении **301 897,3910 мм³**;
- аналитический объём по размерам и 5 сквозным отверстиям **301 858,4086 мм³**, расхождение **0,012914%**;
- сетка содержит **1 076 треугольников**;
- модельное измерение `MASSPROP` давало около **301 858,4119 мм³**, близко к аналитике; различие связано с методом оценки объёма, не следует путать её с точным расчётом.
- Модель не имеет размеров на проекциях, материала, допусков, проверки прочности. **Для производства пока непригодна**.
