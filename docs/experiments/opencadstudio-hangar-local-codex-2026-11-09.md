# Локальный Codex CLI на HangarVPS для OpenCADStudio — 09.11.2026

**Цель:** отказаться от сетевой цепочки BruceVPS → HangarVPS при исполнении CAD. Подключить Codex на самом HangarVPS к локальному MCP OpenCADStudio v2026.45, авторизовать через штатный вход ChatGPT.

## Реально выполнено

- На `hangarvps` (Ubuntu 24.04.5, x86_64) установлена **Codex CLI 0.167.0** из официального npm `@openai/codex@0.167.0`. Бинарник `/usr/bin/codex` проверен через `codex --version`. Node 24.22.2, npm 11.19.1.
- Выбран ранее созданный изолированный пользователь `ocstest` (UID 995, домашний каталог `/home/ocstest`, системный shell `/usr/sbin/nologin`). **Codex не запускается под root**, кроме короткой оболочки `runuser`, которая сбрасывает полномочия.
- `/home/ocstest/.codex/config.toml` (права 0600, принадлежит `ocstest`) содержит локальный MCP `opencadstudio`:
  `/usr/bin/xvfb-run -a -s '-screen 0 1440x960x24' /home/ocstest/opencadstudio/OpenCADStudio-v2026.45-linux-x86_64.AppImage --mcp`.
  Проверено `codex mcp list` и `codex mcp get opencadstudio --json`. Статус MCP **enabled**, никаких межсерверных транспортов нет. Сам OpenCADStudio MCP успешно испытывался в прежних этапах, но ещё не запускался именно из авторизованной сессии Codex.
- Создана оболочка **`/usr/local/bin/codex-cad`** (root:root, 0755). Она запускает `codex -C /home/ocstest/opencadstudio -s workspace-write` от `ocstest`, в том числе при запуске от root. Проверены `codex-cad --version` и `codex-cad mcp list`.
- В рабочей директории создан `/home/ocstest/opencadstudio/AGENTS.md` (права 0640), с правилами использовать локальный MCP, выполнять независимый геометрический аудит, не читать секреты и не изменять системную конфигурацию без запроса.
- Запущен **официальный вход ChatGPT для безэкранного сервера** `codex login --device-auth` от `ocstest` в отдельном `systemd` процессе `codex-hangar-login.service`. Одноразовый код остаётся внутри закрытого файла `/home/ocstest/.codex/device-login.log` (0600). В созданной приватной странице на уже имеющемся авторизованном Termalin-портале владелец видит официальный адрес и одноразовый код; значение **не публиковалось в чат или GitHub**. Страница доступна только после входа в личный кабинет Termalin и временная — добавлен таймер автоматического удаления через 30 минут; никому не передавать код в переписке.
- При последней проверке `codex-cad login status` возвращал **Not logged in**. Пользователю ещё нужно завершить авторизацию в браузере. Не считать авторизацию установленной до подтверждения `login status`.
- Никакие OpenAI API ключи/Bitwarden секреты на HangarVPS не копировались. Существует прежний независимый пилот на Bruce для сравнения; он **не удалён** и не переключён на Codex. Codex при входе через ChatGPT использует права/лимиты рабочей области ChatGPT, а не бонусный баланс API.
- Вход Device Code может требовать включения соответствующего параметра в настройках безопасности ChatGPT/разрешениях рабочей области; это контролирует владелец. По официальным инструкциям OpenAI: https://learn.chatgpt.com/docs/auth и https://github.com/openai/codex .

## Проверка после действия владельца

1. На HangarVPS выполнить `codex-cad login status`, убедиться, что выполнен вход именно в нужную учётную запись ChatGPT.
2. `codex-cad mcp list` подтверждает локальный `opencadstudio enabled`.
3. Проверить доступность желаемой модели (`gpt-6.1-sol`) через реальный пробный вызов: локальный Codex CLI может иметь другой перечень доступных моделей, чем API.
4. В изолированной папке запустить **неразрушительный** небольшой вызов `codex-cad exec --skip-git-repo-check` с просьбой перечислить доступные MCP инструменты и построить отдельный тестовый чертёж. До проверки прав и сетевой доступности не запускать произвольную установку пакетов или полномасштабные задачи.
5. Должен появиться новый DWG/PDF/PNG **без** SSH к BruceVPS, с реальным журналом обращений Codex к MCP; проверить `audit`, объём, габариты и повторное открытие.

## Ограничения

- Codex установлен и MCP добавлен, **но сквозная работа Codex→MCP после входа ещё не проверена**, не выдавать за завершённый испытательный цикл.
- Перед промышленной эксплуатацией проверить полномочия Codex и наличие механизма повторной авторизации; запускать только непривилегированно с ограниченным доступом.
- Внешняя программная связка BruceVPS и ключ OpenAI остаются в системе, но больше **не нужны для нового локального пути**, удалять их без отдельного решения не требуется.
