# Источнико-зависимые 2D-сечения из 3D OpenCADStudio на Ангаре — 12.11.2026

**Результат: PASS для автоматической регенерации трёх сечений из сохранённого 3D DWG.** В отличие от двух предыдущих испытаний, где **GPT-6.1 Sol через Codex** самостоятельно создавала объёмный DWG и отдельно чертила 2D по размерам, этот этап исполнен **проверяемой локальной программой на Python**, взаимодействующей с реальным движком OpenCADStudio `--serve`. Sol остаётся основным чертёжным агентом на HangarVPS, в её `AGENTS.md` закреплён вызов регенератора.

Важно не подменять термины: **это геометрические сечения исходного 3D-тела и перестроение по SHA-256, НЕ нативные ассоциативные проекции видимых рёбер**, не полный производственный чертёж и не автоматический фоновый следящий процесс. Для обновления после изменения DWG регенератор должен быть вызван снова (в том числе самим Codex).

## Отчего отказались

В установленном `OpenCADStudio v2026.45` есть `FLATSHOT`. Буквально без выбора тела возвращает ошибку `select a solid created this session`; при явном выборе даже ранее сохранённого B-rep работает. Однако для испытательной плиты он создаёт **692 отрезка: 16 нулевой длины; 344 уникальных ненулевых; ещё 332 совпадающих дубликата**. Существеннее: при командах `-VIEW _TOP`, `-VIEW _FRONT`, `-VIEW _RIGHT` в головном и графическом режимах получаются **одинаковые 692 отрезка в XY**, хотя камера графического режима действительно меняется. Прямое использование `FLATSHOT` для трёх ортогональных видов в текущей сборке отвергнуто. Это результат реального черного-ящичного опыта, а не объявление об отсутствии функции в других САПР.

## Работающий способ

Через штатную команду `SECTION` непосредственно на **сохранённом одном 3D Solid**:
- `SECTION Z 6` — сечение основания по Z=6 мм: **6 замкнутых контуров**, 650 исходных рёбер (внешний + пять отверстий).
- `SECTION Y 70` — продольный вертикальный разрез: **2 замкнутых контура**, 100 исходных рёбер.
- `SECTION X 100` — поперечный вертикальный разрез: **2 замкнутых контура**, 72 исходных ребра.

На каждом сечении проверены замкнутость циклов и степень 2 у всех вершин без угадывания геометрии. Из горизонтального сечения автоматически распознаны пять круглых отверстий с точными центрами **(20,20), (20,120), (100,70), (180,20), (180,120)** и радиусами **5, 5, 13, 5, 5 мм**. Их приближённые многосегментные петли преобразованы в настоящие `Circle`; коллинеарные отрезки сгруппированы в `Polyline`. Оба вертикальных сечения преобразованы в отдельные замкнутые плоские контуры.

Дальше новый документ создаётся через OpenCADStudio `--serve` с **5 Polyline, 5 Circle, 4 Dimension, 6 исходными Text**, проходит `audit 0/0`, сохраняется `save_verified verified=true` как DWG2018 и строится PDF через `plot`. Размерные величины 200/140/40 мм берутся из **фактически измеренных габаритов исходного 3D**. Никакого ручного повторного ввода контуров в результирующий DWG нет.

Код: [tools/opencadstudio/regenerate_sections.py](../../tools/opencadstudio/regenerate_sections.py); расположен на HangarVPS: `/home/ocstest/opencadstudio/regenerate_sections.py`, выполнение от `ocstest`.

Одноразовая регенерация:

```bash
python3 /home/ocstest/opencadstudio/regenerate_sections.py /home/ocstest/opencadstudio/results/sol-pilot/codex-real-20261112-ribbed-plate.dwg
```

Выход: отдельные DWG/PDF/JSON в `results/sol-pilot/derived-sections/`, имя содержит **первые 12 знаков SHA-256 исходника**. При повторном запуске для неизменённого исходника данные переиспользуются без перезаписи. Исходные 3D файлы не редактируются; перед приёмкой проверяется неизменность SHA-256.

## Независимая проверка изменений

Для проверки создана **отдельная копия-модификация** модели — к основной плите добавлен и через `UNION` присоединён объёмный выступ 20×25×12 мм; в результате габарит X изменился **200→220 мм**, прочие габариты не изменились. Исходный 3D DWG остался нетронут.

| | Исходная 3D-модель | Изменённая копия |
|---|---|---|
| Source SHA-256 (12 знаков) | `be4c4086670e` | `e28f0ab075a2` |
| Габарит X | 200 мм | 220 мм |
| Контур Z=6 | Прямоугольник из 4 вершин | Контур с выступом из 6 вершин |
| Отверстия | 5 | 5 |
| Сечения Z/Y/X | 6 / 2 / 2 петли | 6 / 2 / 2 петли |
| Надпись размера X | `200` | `220` |
| Объекты DWG после повторного открытия | 5 Circle / 5 Polyline / 4 Dimension | То же |
| Независимый аудит | 0 ошибок, 0 предупреждений | 0 ошибок, 0 предупреждений |

Для обоих итоговых DWG произведено **независимое повторное открытие другим экземпляром OpenCADStudio**; проверены исходные контрольные суммы, значения размеров 200/220, объекты, корректность PDF. Повторный вызов регенератора на прежнем исходнике вернул `reused=true`.

Актуальная версия регенератора — **v2**. Она отдельно маркирует лист **`ДЕМО_НЕ_ДЛЯ_ИЗГОТОВЛЕНИЯ`**. Ранее полученные файлы v1 сохранены как промежуточные свидетельства; для демонстрации использовать v2.

## Ограничения и дальнейший смысл

1. В v2 плоскости сечения **фиксированы** (Z6/Y70/X100) и строго проверяется топология конкретного образца (6/2/2 петли, пять окружностей, ровно одно 3D-тело). **Не запускать для произвольной детали** без параметризации плоскостей и адаптации проверки; отказ считается правильным.
2. `SECTION` создаёт *разрез материала*, а не стандартный ортогональный внешний вид с видимыми и скрытыми рёбрами. Нельзя подменять эти виды в ЕСКД. Положение разреза и направление должно быть явно обозначено.
3. Прямой ассоциативности элементов внутри файла DWG пока нет; при изменении B-rep нужен повторный запуск этого воспроизводимого процесса. Внутри выходных файлов идентичность источника записывается также в JSON-манифест и надпись на листе.
4. Размеры/подписи пока слишком мелкие для рабочего формата, нет материала, допусков, штампа, технических требований и проверки прочности. Демонстрация **не пригодна для изготовления**.
5. Следующий шаг — перевести построитель на **выбираемые плоскости, разные типы деталей, автоматическое обозначение секущих плоскостей**, затем внедрить запуск по событию успешного сохранения 3D в локальном Codex (без отдельного фонового сервиса) и проверять разнообразные детали.
6. Sol на AngarVPS сохраняет авторизацию ChatGPT; новое испытание с новой модельной сессией для создания сечений **не потребовалось** — проверяемые детерминированные операции выполнялись напрямую, чтобы избежать большого расхода токенов. Доказательство, что Sol сама сможет вызвать этот построитель как инструмент после сохранения, ещё впереди.
