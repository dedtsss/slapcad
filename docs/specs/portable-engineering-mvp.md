# КолхозCAD: переносимая инженерная среда — спецификация первого рабочего контура

Дата: 2026-10-24. Статус: **согласованная цель и требования; технические кандидаты ещё подлежат испытанию; реализация не начата**.

## 1. Результат для пользователя

Пользователь управляет проектированием на русском языке из ChatGPT, Hermes или другого агента: «добавь три отверстия», «покажи расстояние», «перемести кронштейн», «подбери положение рессоры». Он **не открывает CAD-редактор** и видит проверяемый снимок с размерами в чате и обновляемую 3D-модель по одной защищённой ссылке в браузере телефона.

Инженерный комплекс и его данные независимы от OpenAI, Workspace Agents, Hermes, MCP и одной конкретной CAD-программы. GitHub — каноническое хранилище проекта/решений; долговременные расчётные артефакты и модели имеют воспроизводимые версии и проверяемые идентификаторы.

## 2. Архитектурный инвариант: независимое ядро, сменные клиенты

- **Ядро:** запускаемые локально команды/программа с определённым машинно-читаемым входом (операция/параметры/проект/версия), выходом (состояние, метрики, пути/ссылки на артефакты, ошибки) и кодом завершения. На первом этапе достаточно CLI + JSON, без микросервисной платформы.
- **Геометрия:** параметрический исходный код (CadQuery или build123d), AgentCAD как кандидат на исполнение/проверку/сравнение, FreeCAD только по подтверждённой необходимости (чертежи/сборки и специфические операции), ezdxf, CalculiX/Gmsh по доказанной потребности. Не считать STEP параметрической историей; сохранять исходники, координатную схему и таблицу параметров.
- **Транспортные адаптеры:** один способ выполнения из Workspace Agent (готовый Remote Desktop Commander или тонкий универсальный MCP), локальный CLI/SSH для Codex/Hermes. MCP содержит только транспорт и управление заданиями, **не** CAD-алгоритмы, политики и знания. Не создавать по отдельному инструменту на каждую операцию.
- **Навыки и правила:** переносимые, хранимые в репозитории инструкции/шаблоны навыков с понятной точкой входа для разных агентов. В Workspace копируется/подключается только минимальный указатель и клиентская конфигурация. Важно: текст навыка не гарантирует доступ к инструментам; у каждого клиента должна быть проверенная действующая возможность вызвать ядро.
- **Данные:** проектно-ориентированные каталоги; исходная измеренная конструкция — неизменяемая база; варианты — отдельные воспроизводимые версии. Публикуются STEP, GLB, PNG, DXF/PDF, параметры и отчёт о проверках. Крупные двоичные артефакты — в файловом хранилище с хешами/резервной копией, не засорять Git.
- **Просмотр:** браузерный 3D-предпросмотр через защищённую постоянную ссылку проекта; запуск без отдельного редактора. Использовать готовый AgentCAD viewer, если его безопасность/доступ с телефона удовлетворяют требованиям; иначе готовый простой GLB-просмотрщик. Страница получает только успешно проверенную новую версию, сохраняет возможность поворота/масштаба и сравнения версий.
- **Изоляция:** выделенный каталог и пользователь/контейнер на подходящем VPS, без доступа к хостовым секретам, чужим профилям браузеров, Docker socket и другим проектам. Внутри инженерного контура агент имеет полноценный доступ к Python, установленным пакетам и проектным файлам, без перечня запретов по видам CAD-операций.

## 3. Поиск практического опыта обязателен

Перед выбором конструкции/узла агент должен при необходимости исследовать: официальные характеристики/нормы, аналоги изделий и применённые переделки, DRIVE2/форумы, профильные сообщества, GitHub, видео/разборы и прежде всего проблемы, отказы, жалобы, контрпримеры. Не ограничиваться краткими выдержками и рекламными материалами.

Отчёт различает: измеренные факты, нормативные обязательства, расчётные предположения, пользовательский опыт и инженерные рекомендации. Для источников сохранять ссылки, дату, описанные условия эксплуатации и применимость. Несоответствия между расчётом и практикой требуют объяснения (масса, жёсткость, демпфирование, геометрия, допуски), а не слепого выбора одной стороны.

Недопустимо подменять обязательные требования или проверку силовых соединений доводом «на форумах все так делают». Для ненагруженных элементов допускаются обоснованные упрощения с явным указанием ограничений. Критические решения по подвеске, тормозам, сцепному устройству, устойчивости и безопасности эксплуатации требуют отдельной проверки и соблюдения применимых требований.

## 4. Последовательность реализации (только после отдельного разрешения запуска)

**Этап A — доказательство работоспособного ядра без инфраструктуры.** Сопоставить реальные возможности/лицензии версий AgentCAD, CadQuery, build123d, FreeCAD, просмотрщика и других компонентов. Выбрать минимальную связку. Реализовать один воспроизводимый вызов CLI: модель гнутого профиля/лонжерона, отверстия, проверка валидности, экспорт STEP/GLB/PNG/DXF и структурированный JSON-отчёт. Проверить отсутствие зависимости от API OpenAI/MCP.

**Этап B — изолированная среда VPS.** Прежде чем размещать, проверить CatVPS/альтернативные хосты и доступный объём памяти в рабочем профиле (нормальная работа ориентировочно 1–3 ГБ, одновременные тяжёлые процессы/МКЭ могут превысить 8 ГБ). Подготовить воспроизводимую установку и предел параллелизма, запуск по запросу, очистку временных файлов, автоматическое восстановление после перезапуска; не затрагивать MarketAgent, секреты и другие системы.

**Этап C — клиентские адаптеры без привязки к поставщику.** Сначала проверить, можно ли из Workspace Agent штатно подключить существующий универсальный терминал к ограниченной инженерной среде; затем, только если он не подходит, реализовать минимальный стабильный MCP-адаптер/туннель. Показать запуск того же сценария напрямую через CLI и через один клиентский адаптер; отдельно проверить независимость от OpenAI через Hermes/другой доступный агент либо CLI с документированным планом дальнейшего клиентского теста. Исходный движок при смене клиента не меняется.

**Этап D — просмотр на мобильном телефоне.** Защищённая постоянная ссылка проекта, обновление последней проверенной модели без скачивания файлов, масштаб/поворот/изолирование элементов, сохранение правильной ревизии и отображение размеров (на изображении/чертежах и по запросу). Проверка на реальном мобильном браузере, без открытого публичного доступа к файлам и без установки CAD-приложения.

**Этап E — правила и исследовательский контур.** Хранящиеся в Git навыки/инструкции для восстановления по фото+обмерам, параметрического редактирования, геометрических измерений, 2D-чертежей, инженерных расчётов и поиска практического опыта. Автоматические проверки каждой операции: валидность тела, требуемые размеры/единицы, отверстия, отсутствие незапланированных изменений, маркировка неопределённостей. Показать на примере рессор/кронштейнов комбинированный отчёт: нормы, практический опыт, расчёт и ограничения.

**Этап F — контрольный пользовательский сценарий.** Для TODOMA при наличии доступных исполнителю фотографий/видео и подтверждённых обмеров сделать исходную сборку с корректными профилями и отверстиями. Отдельно показать команду добавления трёх отверстий, изменение их положения, измерение расстояния, возврат к прежней версии, чертёж, 3D-просмотр и исследование варианта крепления подвески. Не выдумывать отсутствующие размеры и не выдавать визуально оценённые параметры за измеренные. Пока числовые обмеры не переданы исполнителю, можно демонстрировать систему на явно синтетическом образце; приёмка реальной TODOMA требует достоверных размеров.

## 5. Проверяемое качество

- Отдельная команда CLI воспроизводит модель после перезагрузки/переноса исходников без ChatGPT.
- Смена клиентского агента не меняет исходники геометрии, формат данных, навыки, ссылку на 3D-проект или хранилище.
- Каждый шаг сохраняет идентификатор ревизии, входные значения, проверенные метрики, версию инструмента, ошибки и ссылки на артефакты.
- Успешная операция создаёт проверенный результат, неудачная не заменяет опубликованную модель и не портит исходник.
- Чертёж и размерные обозначения согласованы с 3D и измерены из геометрии, а не извлечены из картинки.
- Доступ/сети/права проверяются именно из будущей среды исполнения; работа не сводится к наличию установленных пакетов.
- Полный резерв/восстановление состояния проекта проверены на копии. Секреты и доступ к другим VPS-проектам не передаются инженерному процессу.
- На практике продемонстрирована последовательность «сообщение агенту -> изменение -> проверка -> обновлённая модель на телефоне». Работу принимать по этому сценарию, не по скриншоту установки.
- Результаты расчётов прочности имеют исходные нагрузки, материал, граничные условия и применимость; экспериментальное ПО не считается сертифицированной инженерной экспертизой.

## 6. Границы и нерешённые вопросы

- Пока **не утверждены**: точный VPS, исполнение через готовый терминал или собственный тонкий MCP, обязательность FreeCAD/CalculiX в первом этапе, способ защищённой веб-публикации, конкретный адаптер Hermes и рабочий предел памяти.
- Не разрабатывать собственный CAD-редактор, универсальную платформу агентов, новый оркестратор, отдельное мобильное приложение или сложную базу данных без доказанной необходимости.
- Не разворачивать и не менять VPS, туннели, доступы, службы и Workspace Agent **до отдельного разрешения владельца на исполнение**.
- Workspace Agent вручную создаёт/подключает владелец после готовности клиента; его настройки не являются каноническим местом хранения правил.
- Перед исполнительным запуском проверить актуальные `docs/task-rules.md` в `dedtsss/agent-dispatch`; предзапусковые проверки исходных файлов/секретов/рабочих прав проводить из фактического окружения исполнителя.
- Если реальную модель TODOMA нельзя проверить по исходным размерам, не подменять это приблизительной «точной» CAD-копией.
